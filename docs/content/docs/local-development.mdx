Use this page if you are working on `pdf-raster` itself inside the
monorepo. If you only want to install and use the package, start with
[Installation](/docs/installation).

## Prerequisites

- Bun 1.4.2 (the version pinned in `packageManager`)
- Rust (stable)
- Node.js 24 or newer

## Local development flow

<Steps>
  <Step>
    Download or refresh the local PDFium cache:

```bash
bun run pdfium:download
```

  </Step>
  <Step>
    Build the native package:

```bash
bun run --filter pdf-raster build
```

  </Step>
  <Step>
    Run the package tests to validate the local native path:

```bash
bun run --filter pdf-raster test
```

  </Step>
</Steps>

## If the native setup breaks

<Steps>
  <Step>
    Make sure the package is built for the current platform.
  </Step>
  <Step>
    Refresh the local PDFium cache with `bun run pdfium:download`.
  </Step>
  <Step>
    Rebuild the package with `bun run --filter pdf-raster build`.
  </Step>
  <Step>
    Run `bun run --filter pdf-raster test` to validate the native
    path.
  </Step>
</Steps>

## Releasing

- Add a changeset with `bun run changeset` for every package-affecting change.
  CI enforces this.
- Merging to `main` makes the Release workflow open or update a "Version
  Packages" pull request.
- Merging that pull request publishes all 7 packages from `main` with
  provenance.
- Running the Release workflow with `workflow_dispatch` on any other branch
  builds and smoke-tests all 6 targets but never publishes.
- `bun run release:publish -- --dry-run` (or
  `bun scripts/publish-packages.ts --dry-run`) checks packaging without
  publishing (it requires all six native artifacts in `core/artifacts/`, for
  example downloaded from a Release workflow run). A bare `npm publish` in `core/` is intentionally refused.
