This page is for working on pdf-raster itself. To use the package, start with
[Installation](/docs/installation).

## Prerequisites

- Bun 1.4.2, the version pinned in `packageManager`
- Rust, stable toolchain
- Node.js 24 or newer

## Build and test

<Steps>
  <Step>
    Install dependencies:

```bash
bun install
```

  </Step>
  <Step>
    Download PDFium into the local cache:

```bash
bun run pdfium:download
```

  </Step>
  <Step>
    Build the native package:

```bash
bun run --filter pdf-raster build
```

  </Step>
  <Step>
    Run the tests. They rebuild the package, then run under Bun and Node.js and
    check concurrent initialization:

```bash
bun run --filter pdf-raster test
```

  </Step>
</Steps>

## Repository layout

| Directory | Contents |
| :-------- | :------- |
| `core/` | The published `pdf-raster` package, in Rust and TypeScript |
| `docs/` | This site, built with Next.js and Fumadocs |
| `benchmark/` | Comparisons against pdfjs-dist |
| `example/` | A demo app that uses the local workspace package |
| `consumer/` | A minimal Next.js app that installs pdf-raster from npm |

## When the native build breaks

1. Run `bun run pdfium:download` to refresh the PDFium cache.
2. Rebuild with `bun run --filter pdf-raster build`.
3. Run `bun run --filter pdf-raster test`.

If `convert()` still throws `PDFIUM_UNAVAILABLE`, check that `PDFIUM_LIB_PATH`
is unset or points to a library built for your platform.

## Releasing

- Every change that affects the package needs a changeset. Create one with
  `bun run changeset`. CI fails without it.
- Merging to `main` opens or updates a "Version Packages" pull request.
- Merging that pull request publishes all 7 packages, `pdf-raster` and its 6
  platform packages, from `main` with npm provenance.
- Running the Release workflow by hand (`workflow_dispatch`) on another branch
  builds and smoke-tests all 6 targets without publishing.
- `bun run release:publish -- --dry-run` checks the packaging without
  publishing. It needs all 6 native artifacts in `core/artifacts/`, which you
  can download from a Release workflow run.

Running `npm publish` in `core/` fails on purpose. Publish only through the
release script.
