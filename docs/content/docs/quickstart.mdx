title: Quickstart
description: Render PDF pages from a file path or a buffer, pick pages and choose an output format.
---

Everything in pdf-raster goes through `convert(input, options?)`. This page
covers the options you will use first.

## Render every page

```ts
import { writeFile } from "node:fs/promises";
import { convert } from "pdf-raster";

const pages = await convert("./report.pdf");

for (const page of pages) {
  await writeFile(`page-${page.pageIndex + 1}.png`, page.data);
}
```

Without options, pdf-raster renders every page at 300 DPI and encodes each one
as PNG.

## Read the result

`convert()` resolves to an array with one `ConvertedPage` per rendered page:

```ts
const [page] = await convert("./report.pdf");

console.log(page);
// {
//   pageIndex: 0,
//   data: <Buffer 89 50 4e 47 ...>,
//   mimeType: "image/png",
//   width: 2550,
//   height: 3300,
//   dpi: 300,
// }
```

`data` holds the encoded image. You can write it to disk, return it from an
HTTP handler or pass it to another library as is.

## Render selected pages

`pages` takes zero-based indices. The result follows the order you list them
in:

```ts
const pages = await convert("./report.pdf", {
  pages: [0, 2], // the first and third pages
});
```

An index past the last page throws `INVALID_PAGE_INDEX`.

## Choose an output format

```ts
const pages = await convert("./report.pdf", {
  outputFormat: "webp",
});

console.log(pages[0].mimeType); // "image/webp"
```

| Format | Compression | When to use it |
| :----- | :---------- | :------------- |
| `png` (default) | Lossless, fast | The fastest encode. Files are the largest. |
| `webp` | Lossless | About a third of the PNG size on text pages. |
| `jpeg` | Lossy, quality 75 | The smallest files for pages with photos or scans. |

The [benchmark](/docs/benchmark#output-size) lists measured sizes for each
format.

## Pass bytes instead of a path

If the PDF is already in memory, pass a `Buffer`, `Uint8Array` or
`ArrayBuffer`. pdf-raster does not write a temporary file.

```ts
const response = await fetch("https://example.com/invoice.pdf");
const pages = await convert(await response.arrayBuffer(), { dpi: 150 });
```

## Other options

```ts
const pages = await convert("./statement.pdf", {
  dpi: 200,
  password: "s3cret", // for encrypted PDFs
  crop: { x: 0, y: 0, width: 1700, height: 600 }, // in rendered pixels
  renderAnnotations: false, // skip comments and form field values
  maxPixels: 50_000_000, // reject pages larger than this
});
```

The [API reference](/docs/api-reference) describes each option and its
default.

## Common questions

<Accordions type="single">
  <Accordion title="Why do page indices start at 0?">
    `pages` is an array of indices, like any JavaScript array. Use `pages: [0]`
    for the first page. `page.pageIndex` uses the same numbering.
  </Accordion>
  <Accordion title="Why does it return buffers instead of writing files?">
    Most callers send the image somewhere else, such as an HTTP response, object
    storage or an OCR engine. A buffer skips the disk round trip. Use
    `writeFile` when you do want a file.
  </Accordion>
  <Accordion title="Which DPI should I use?">
    300 DPI suits OCR and vision models and is the default. 72 to 150 DPI is
    enough for thumbnails and on-screen previews, and it renders faster with
    smaller output.
  </Accordion>
</Accordions>
